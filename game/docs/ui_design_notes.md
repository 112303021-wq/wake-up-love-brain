# UI 設計說明

## 設計決策
- **手機優先**：容器最大 480px 置中；觸控目標一律 >= 44px；輸入列、選項區吃 `safe-area-inset-bottom`。
- **LINE 風格**：我方氣泡在右（主色）、對方在左（白／深色面）並有頭像；聊天區底色是淡粉，與輸入區分層。
- **教練插話區隔**：置中、黃色底、左側粗邊、標題「🔥 罵醒教練（尺度）」，稱讚時改綠色。顏色之外還有位置與標題差異，不單靠顏色。
- **紅旗回饋**：每則 NPC 訊息旁 🚩 鈕（44px）；檢舉後有彈跳動畫、氣泡紅框、標籤顯示紅旗意義（綠=抓對、紅=漏、粉=開發者揭露）。誤判顯示「這句其實沒問題」。
- **階段進度**：5 段進度條（目前階段加外框，第 5 階段用紅色），並有 aria-label「第 N 階段，共 5」。
- **尺度滑桿**：橫軸三段「溫柔／毒舌／地獄」固定標示，右側即時顯示目前值；`aria-valuetext` 為中文名稱。
- **人格卡片**：每個人格有專屬色條（依 `data-p`）、emoji、tagline、當前性別下的名字與年齡、存檔進度。性別為 radiogroup，切換後卡片名字即時更新。
- **結算視覺化（純 CSS/SVG）**：SVG 圓環=清醒分數；水平條=紅旗辨識率；綠到紅漸層加指針=受影響程度（後端欄位仍為 fooled_index）；雙色分段條=清醒 vs 戀愛腦回覆。逐句覆盤用氣泡加狀態色框（抓到綠／漏掉紅）。
- **無障礙**：文字對比 >= 4.5:1（淺色主色 #c8264d 白字約 5.5:1）；`:focus-visible` 藍色 3px 外框；對話框開啟時焦點進入、關閉時還原、Esc 關閉（後端觸發的安全提示除外，必須按按鈕）；聊天區 `role=log aria-live`；圖表附文字數值與 aria-label；`prefers-reduced-motion` 關閉動畫；有「跳到主要內容」。
- **深色模式**：預設跟隨系統，右上 🌓 可手動切換並存 localStorage。
- **危機資源**：首頁、選角頁、聊天頁頂端都有 🆘 鈕，開啟 1925/165/113 的 `tel:` 連結。後端觸發的安全 modal 沿用原本流程。
- **預留入口**：首頁、選角頁、結算頁底部放「小測驗／暈船互助會／成就」，點開顯示「即將推出」說明，未接後端。

## 畫面清單
1. 首頁（暱稱、開始、三個預留入口、🆘、主題切換）
2. 選對象（性別、5 張人格卡、教練紀錄、預留入口）
3. 聊天（頂欄、進度條、尺度滑桿、對話、選項、輸入列、開發者面板）
4. 結算 modal（分數圓環、三張圖表、教練總評、逐句覆盤、預留入口）
5. 安全提示 modal（後端觸發）／🆘 危機資源 modal／即將推出 modal／prompt 檢視 modal

## 未解決問題
- 未在真機或螢幕閱讀器（VoiceOver/TalkBack）實測，對比值為估算。
- Modal 尚未做完整 focus trap（只做進入/還原焦點與 Esc）。
- 教練標題的尺度取自滑桿目前值，舊訊息可能與當時不同（見 ui_backend_requests.md #4）。
- 人格顏色寫在 CSS，未來新增人格需補 CSS；階段數寫死 5。
- 危機電話號碼在前端重複一份（見 #9）。
- 逐句覆盤只有 NPC 紅旗句，沒有玩家當時回覆（見 #6）。
- 未做瀏覽器自動化截圖測試，只做了語法檢查與伺服器載入檢查。

# 第 3 輪更新（對應新後端契約）

`docs/api_contract.md` 在本輪結束時尚未產生，以下依 backend_a/b changelog 與 server.py、tests 實際行為實作，契約出爐後需對照一次。

## 這輪做了什麼
1. **選項**：選項只渲染 `text`，樣式與位置一律相同，沒有任何依 kind 或索引的樣式；數量不固定。
2. **結算**：局中按鈕為「結束並結算」，會先跳確認（結束後不能再標 🚩），確認後送 `finish:true`；局已結束則顯示「看結算」。結束後 🚩 鈕 disabled（已標的保留紅框、未標的隱藏）；若仍收到 400 locked/ended，toast「這局已結束，不能再補標紅旗了」並用 `/api/start` 同步狀態。
3. **尺度**：預設溫柔（`lb_sev` 預設 1，也讀 `/api/profile` 的 prefs 並用 `POST /api/prefs` 同步）。選毒舌/地獄會顯示提醒條；選地獄跳確認視窗（文案取自 ethics 1.2：切回溫柔／我了解，繼續），每次切到地獄都確認。另加「靜音教練」「我不舒服」（切回溫柔）與固定小字「教練在評你的選擇，不是在評你這個人」。
4. **safety**：終局類別用 modal，`pause` 標題「已暫停」，後端回 `can_resume` 時有「回到遊戲」（`POST /api/resume`），否則「重新開始這個對象」；`ai_identity`（info）用藍色說明、不顯示資源卡、不用危機視覺；`ends_session:false` 的 low 以聊天內溫和提醒卡顯示（含 tel 連結），支援 `st.notice` 與 `role=system` 帶 `safety` 的訊息，不終局。
5. **讀 API**：`/api/personas` 的 `color`（卡片色）、`description`、`difficulty`（★ 與 aria-label，假設 1–3）、`stage_total`（進度條段數）；`GET /api/resources`（🆘 與卡片）；`POST /api/prefs`。全部有前端 fallback。
6. **逐句覆盤**：顯示階段、`msg_id`、NPC 句，以及玩家當時回覆（`player_reply`，右側氣泡）。
7. **首頁**：知情同意短版 + 18 歲勾選（未勾不能開始）+「刪除我的資料」（確認後 `DELETE /api/profile?player=ID`，並清掉 localStorage、換新玩家 ID）。
8. **稱號**：結算稱號由前端依分數顯示中性分級（火眼金睛／警覺升級／觀察中／新手上路），不再顯示後端 `grade`/`grade_note`；教練總評文字中的舊稱號會被替換為中性詞。
9. **開發面板**：預設隱藏。前端用 `GET /api/prompt` 是否 404 判斷 GAME_DEV（無專用旗標，見下）；非 dev 不送 reveal/hour。

## 仍未解決的問題

# 第 5 輪更新（對照 api_contract.md 第 5 輪）

## 做了什麼
1. **token**：任何回應頂層的 `token` 會存進 localStorage（`lb_token`，try/catch），之後所有請求帶 `X-Player-Token` header（GET profile、POST、DELETE 都帶）。401/403（用 `code` 或 status 判斷）跳「憑證遺失或不符」確認框，按「重新開始」會清掉本機身分、產生新 ID、回首頁。玩家 ID 用 `crypto.getRandomValues` 產生 21 碼；舊版 ID（>= 8 碼）保留，讓無 token 的舊存檔走契約的認領流程（第一個建立型請求，也就是 `/api/consent`，會簽發 token）。
2. **錯誤 code**：移除字串比對。`handleErr` 依 code 對應中文訊息（rate_limited、quota_exceeded、cooldown、resume_limit、not_resumable、not_started、invalid_choice、not_finished）；429 一律顯示「請稍後再試」；send 遇 ended/not_started/invalid_choice 會用 `/api/start` 重新同步畫面；flag 遇 ended/locked 提示並同步；review 遇 not_finished 重新走確認。
3. **dev**：`GET /api/resources` 的 `dev`，已移除探測 `/api/prompt`。
4. **同意**：進入時若 profile.consent 不是「accepted 且版本等於 `v1-2026-11`」才顯示同意區塊與勾選；按「開始練習」時 `POST /api/consent`。已同意則顯示「你已同意（重看說明）」。靜音教練存 `mute_coach`、「我不舒服」存 `{severity:1, feel_uncomfortable:true}`，都由 profile 還原；`feel_uncomfortable` 為真時滑桿鎖在溫柔並顯示說明，按鈕變「解除」。靜音後前端不再過濾教練訊息（後端不產生）。
5. **稱號**：移除前端分級與字串替換，直接顯示後端 `grade`、`grade_note`、教練 `comment`。
6. **刪除確認框**：改為實際行為（存檔含暱稱／對話／分數、同意紀錄、損毀隔離檔；不可復原；本機換新身分）。
7. **選項 3~4 個**：選項區依內容堆疊並可捲動；矮螢幕（高度 <= 680px）縮小高度上限與內距；`meta:true` 的玩家訊息用虛線氣泡加「問身分・不計分」標籤，且畫面完全不依賴 `kind`。
8. **too_painful**：「回到遊戲」先開確認視窗（資源 + 「我還需要休息／我現在可以繼續」），再送 `confirm:true`；`cooldown`、`resume_limit` 顯示說明並隱藏回到遊戲、只留重新開始；pause 直接 resume。安全提示與低風險提醒都註明「原文沒有被保存」。`category:'model'` 仍走通用文案出口（fallback）。
9. **無障礙**：對話框焦點鎖定（Tab/Shift+Tab 循環、焦點跑出時拉回）；開啟時背景 `.screen` 與下層對話框設 `inert`；焦點還原改為堆疊，巢狀對話框可正確還原；Esc 規則不變（安全提示不能用 Esc 略過）。

## 對比檢查（腳本算出，WCAG 相對亮度）
用 node 腳本讀 `style.css` 的色彩 token 計算（腳本放在 session scratchpad，不屬於專案）。淺色／深色共 25 組文字或非文字配對**全部通過**（文字 >= 4.5:1，邊框與焦點 >= 3:1）。最低幾組：淺色 accent/accent-soft 4.55、accent/chat 背景 4.81、good/good-soft 4.97；深色最低 accent/accent-soft 5.33。其餘：ink/surface 淺 16.2、深 14.6；accent-ink/accent 淺 5.47、深 6.61；ink-2/surface 淺 8.15、深 8.26。檢查過程發現人格色（如橘 #e08a1e）當文字色對比不足，已把難度星星改為 ink-2；人格色只用在左側色條與 emoji 底色。
限制：只算了 token 配對，沒有逐一量實際渲染結果（例如 color-mix 的聊天背景用估算混色）。

## 仍未解決

# 第 6 輪更新（對照 api_contract.md 第 6 輪）

## 做了什麼
1. **授權**：沒有儲存 token 時不呼叫 `GET /api/profile`（直接當新玩家）；所有 401 一律走「憑證無效」流程（不再依賴 403 或 `not_started`，兩者的處理都移除）。舊使用者（localStorage 有舊 ID 但沒有 token，或 ID 短於 16 碼、或沒有新版 ID 標記 `lb_idv`）會看到「需要重新開始」確認框，只有按下才產生新 ID；在那之前按「開始練習」只會再次彈出提示，**不會自動重送舊 ID 的建檔請求**。
2. **結算流程**：新增三種畫面階段 `phaseOf(state)`：進行中、最後確認（自然結束、未結算）、已鎖定（已結算或安全終止）。最後確認階段：所有 NPC 訊息（含最後一則）的 🚩 仍可按，聊天區底部出現虛線框「最後確認：還有想補標的可疑訊息嗎？」，輸入框說明，右上按鈕變「看結算」，按下會再確認一次（看了就不能補標）才呼叫 `/api/review`；成功後再呼叫 `/api/start` 取得完整標示的 state 重繪。已鎖定時 🚩 停用，若仍收到 `locked` 會提示並重新同步。重新整理頁面：因為後端沒有 `reviewed` 欄位，改用「所有 NPC 訊息是否都帶 red_flags」推斷（已結算／安全終止後都帶，自然結束未結算時未檢舉的沒有）。已用 curl 驗證這個差異存在。
3. **429**：`rate_limited`＝「操作太頻繁，請稍等再試」；`quota_exceeded`＝「目前無法建立新玩家（已達上限），請晚一點再試」；無 code 的 429 當作 rate_limited。
4. **教練 `tone:"neutral"`**：標題「教練備註」，白底、灰色左邊條、無 👍/🔥，與稱讚（綠）和吐槽（黃）都不同。
5. **安全限制白話**：首頁最上方固定一條常駐黃色提示「本遊戲不能偵測所有危機情況。若你現在不舒服，請直接聯絡 1925／165／113」（電話可點，不需捲動）；同意清單新增一條說明偵測以關鍵字與句型為主、可能漏掉也可能誤判；🆘 求助卡最上方放同一段話。🆘 在首頁、選對象、聊天都在標題列；任何對話框開啟時背景被 inert，所以每個對話框底部另有「🆘 需要幫助？」（安全提示與求助卡本身已有電話，不重複）。
6. **小螢幕**：用已安裝的 Chrome headless 實際截圖（見下）。發現並修掉三個問題：(a) 選項在 flex 容器內被壓縮、文字互相重疊（`.choice{flex:none}`）；(b) 聊天頁在 320x568 時標題列、尺度滑桿、教練按鈕佔滿畫面，對話只剩一條縫 —— 改為「教練尺度：溫柔 ▾」可收合面板（視窗高度 < 700 預設收合，展開後仍有橫軸滑桿），矮螢幕隱藏底部提示；(c) NPC 名稱列被 🆘 蓋住、首頁標題被置中裁掉、求助卡 3 張卡需要捲動 —— 已調整（求助卡改為號碼＋名稱並排）。

## 驗證
- `node --check static/app.js` 通過；pytest 752 項通過。
- curl（GAME_DEV=1 與一般模式各一個 server，指定 PID 關閉）：consent 取 token → start → 連續選第一個選項 12 回合自然結束（ended、safety 為 null、NPC 訊息都沒有 red_flags）→ flag 最後一則（200）→ review（不帶 finish）→ 再 start（全部 NPC 訊息帶 red_flags）→ 結算後 flag 回 400 `locked` → 無 token 刪除 401、帶 token 刪除 200。兩種模式結果一致。
