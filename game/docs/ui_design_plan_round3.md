# UI 設計方案（第 3 輪視覺重做）

設計主管提案。本文件只是方案，未修改 `static/` 任何檔案。流程依 frontend-design SKILL：先 token 草案，再對照需求自我檢討，最後修正定稿。

## 0. 主題與對象（先對齊）
- 產品：教育型文字 RPG，教玩家辨識情感操控與詐騙紅旗。
- 玩家：20 歲上下，手機，繁中。
- 主要工作：讓人「被罵醒」（清醒感），但全程心理安全（可離開、可求助、教練罵選擇不罵人）。
- 世界裡最有特色的東西不是愛心，而是「對話截圖」和「別人替你看出問題的那支筆」。玩家被騙的現場就是聊天紀錄，被救回來的方式也是回頭看紀錄。視覺語言從這裡長出來。

## 1. 誠實檢討：現在踩到哪些 AI 生成味
對照 SKILL 的清單（截圖 v3_home / select / chat / review 為證）：

1. 標題單詞換色：`.home-hero h1 span`，「戀愛腦」單獨變 accent。清單明列的第一個 tell。
2. 標題字距拉開 `letter-spacing: .12em`，加上 `AI 互動 RPG` 膠囊標籤（`.home-badge`）：就是「標題上方的 eyebrow 標籤」，內容也沒有資訊量（玩家知道自己在玩什麼）。
3. 粉紅漸層加點陣：`.home-hero` 的 radial dot + 兩層 radial-gradient + linear-gradient；`.chat` 背景也是點陣加漸層。純裝飾，與主題無關，且「粉紅 + 紫」正是戀愛遊戲預設色。
4. SaaS 卡片套件：`.persona`、`.extra`、`.consent`、`.history-box`、`.sheet` 全是圓角卡，半徑 12/14/16/22 看似不同但沒有層級邏輯；同一個 `--shadow`；hover 上浮 2px（`.persona:hover`，每張卡都有，屬於「每張卡 hover 轉場」）。
5. 左側色條人格卡：`border-left: 6px solid var(--pc)` 是儀表板卡片的常見套路；5 種飽和人格色（藍、粉、橘、綠、紫）像糖果，與嚴肅的「辨識詐騙」不搭。
6. 漸層氣泡加小尾巴：我方氣泡 `linear-gradient(135deg, 粉, 紫)`，另有 `::after` 三角。這是聊天 UI 的預設做法，也讓「我方」成為整頁最搶眼的東西，與教學重點（看對方說了什麼）相反。
7. 結算頁「大數字圓環」：170px 圓環加 44px 大數字，是「大數字加小標籤加漸層」預設英雄的變體；之後又疊了進度條、漸層量尺加指針、雙色分段條，一個 modal 裡有四種圖表，資訊重複（紅旗辨識率、受影響程度、清醒比例講的是同一件事）。
8. 同一組「即將推出」三卡片重複出現 3 次（首頁、選角、結算），而且是完全相同的 3 欄等寬卡片。內容是 placeholder，卻占了每個畫面的視覺重量。
9. 中點串接與全形線：「渣男／渣女｜第 2/5 階段：加深依賴」「宇辰・26 歲」「教練（毒舌）」這類 meta 字串拼接。
10. 圓角膠囊濫用：`.btn`、`.chip`、`.seg`、輸入框全是 999px，所有元件長得一樣，看不出哪個是主要動作。
11. 做對的地方（保留）：SVG 圖示系統一致（24 網格、2px 描邊）；沒有 emoji；教練與選項沒有依 kind 變色；已通過對比檢查。

## 2. 視覺方向（一句話）
**「批改過的對話紀錄」**：整個遊戲像一份被朋友拿紅筆（其實是螢光筆加細紅筆）仔細看過的聊天截圖，冷靜、乾淨、有人在你這邊。不談戀愛，不害羞，不吵。

方向理由：
- 「清醒感」是冷色與留白，不是粉紅。
- 「被罵醒」但安全：批註的對象永遠是「那一句話」，不是人；筆跡只落在訊息上，不落在玩家身上。
- 「花在一處的大膽」只有一個：紅筆批註（見第 5 節）。

## 3. Token 草案

### 3.1 色票（6 個具名色，淺／深）
所有對比值為用 WCAG 相對亮度腳本實算（見第 8 節）。

| 名稱 | 角色 | 淺色 | 深色 |
|---|---|---|---|
| 冷紙 `--paper` | 頁面底色 | `#F1F3F4` | `#0E151C` |
| 墨藍 `--ink` | 主文字、表單框線（框線另取 ink-2） | `#16212B` | `#E8EDF1` |
| 清醒青 `--awake` | 主要動作、我方氣泡、進度、焦點以外的主色 | `#0A6A66` | `#5CCBC2` |
| 批改紅 `--pen` | 唯一的紅：紅旗標記、錯過、危險動作 | `#B8281E` | `#FF8F80` |
| 螢光黃 `--hl` | 教練批語底色、抓到紅旗的螢光 | `#F6E27A` | `#E7C85A` |
| 灰藍 `--mute` | 次要文字、分隔線來源 | `#47545F` | `#A9B7C2` |

衍生（不另算作主色）：
- `--surface`：淺 `#FFFFFF`／深 `#18222C`（NPC 氣泡、輸入框、面板）。
- `--calm`：淺 `#E3EDEC`／深 `#1F2E2E`（教練 calm 版底色，青的極淡版）。
- `--line`：`color-mix(in srgb, var(--ink) 14%, var(--paper))`，發絲線。
- `--focus`：沿用現有藍（淺 `#1A5FD0`／深 `#8AB4FF`），不改。

為什麼是這組：
- 青加紅加黃是「校對」的三個動作（認可、指出、強調），不是戀愛遊戲色。
- 完全移除粉紅與紫。人格不再各自一個糖果色（見第 6 節），改用單一青色調加圖示辨識。
- 避開 SKILL 列出的 tell：不是奶油底加陶土色（`#F4F1EA`／`#D97757`），不是近黑加酸綠，不是報紙發絲線零圓角。冷紙是帶藍的灰白，不是暖米色。
- `--paper` 與 `--ink` 都不是純黑白，但也不是「近黑 `#0B0B0B/#111`」那種中性；深色底帶藍（`#0E151C`）。

### 3.2 字型角色
原則：不載入任何網路字型、不嵌入大型 CJK 字型檔（繁中 OFL 字型即使子集化也數百 KB 以上，且無法預測需要的字）。全部走系統字型，零請求，離線可用。

| 角色 | 用在 | 字型堆疊 | 規格 |
|---|---|---|---|
| 主體黑體 `--f-body` | 全部 UI、對話、同意書 | `"PingFang TC", "Noto Sans TC", "Microsoft JhengHei", system-ui, sans-serif` | 16px／1.6；同意書與長文 15px／1.7；行長 <= 26 全形字（手機自然成立） |
| 標題 `--f-head` | 首頁大標、結算結論句、各頁標題 | 同 body | 粗度 800（PingFang TC 為 Semibold/Heavy），字距 `0`（不再用 .12em）；首頁大標 40px／1.15，其餘 h2 20px |
| 批語楷體 `--f-note` | 教練批語、結算「教練備註」、紅旗標籤的文字 | `"Kaiti TC", "BiauKai", "DFKai-SB", "標楷體", var(--f-body)` | 16px／1.7、粗度 400，不用斜體（楷體本身有手寫感） |

載入策略：
- 沒有 `@font-face`，沒有 `<link>` 字型；堆疊最後一個後備是 `--f-body`，所以 Android（多數沒有楷體）自動退回黑體，版面不壞，只是少了手寫感。
- 這是刻意的降級路徑：楷體是加分，不是結構。所有功能與對比不依賴楷體是否存在。
- 數字用 `font-variant-numeric: tabular-nums`，不引入等寬字型（避免「等寬小標籤」tell）。
- 不使用全大寫標籤，不使用 eyebrow。

### 3.3 版面原則
- 對齊：全部左對齊（含首頁標題與結算結論）。唯一置中的是教練批語區塊（它是從旁插話，位置本身就是資訊，且現有設計要求教練與 NPC 氣泡有位置區隔）。
- 圓角：只用兩級。元件 `--r-s: 6px`（按鈕、輸入框、氣泡、教練區）；面板最上緣 `--r-m: 16px`（只有 modal sheet 頂部）。不再有 999px 膠囊，也不再有 12/14/16/22 混用。
- 陰影：全站只有 modal 後方遮罩，與一個元件陰影都沒有。層次靠發絲線與底色差。
- 分隔：用 1px 發絲線（`--line`）與留白，不用卡片包起來。
- 間距：4 的倍數，區塊間 24px，區塊內 12px。
- 動態：非使用者觸發的動畫全部取消（移除 lvup、hitpulse、typing 之外沒有任何入場）；只留使用者動作的回應（紅筆畫線，見下）。`prefers-reduced-motion` 一律關閉（現有全域規則保留）。

## 5. 花在一處的大膽：紅筆批註
唯一一個令人記住的東西，只出現在兩個時刻：
1. **玩家按旗子標紅旗時**：該 NPC 氣泡裡的文字下方，用 CSS 畫一條 `--pen` 手感波浪底線（`background` 用 inline SVG data URI，是內嵌不是外部資源；或 `text-decoration: underline wavy`），並由左到右「畫出來」約 280ms（`clip-path` 或 `background-size` 過渡）。這是使用者觸發的回應動畫，`prefers-reduced-motion` 下直接顯示完成狀態。
2. **結算頁**：同一支筆再出現，把玩家沒看到的地方畫出來。

為何它能撐起整個產品：
- 它是「被罵醒」的視覺化：不是一個分數，而是一條畫在那句話下面的線。
- 它只指向訊息，永遠不指向玩家，符合心理安全。
- 它是整個畫面中唯一的紅色；紅色出現 = 有人在這句話上做了標記。珍貴，所以有效。
- 不洩漏答案：只有玩家主動標旗後（或進入已結算 `locked` 階段）才會有底線；局中沒有任何預先暗示。

其餘一律安靜克制：無漸層、無陰影、無入場動畫、無 hover 抬升、無膠囊。

## 6. 其他元件規則

- 人格識別：頭像 SVG 保留（含 `.av-*` 類別），但 `--p-*` 五色降飽和且只用在頭像環與底色，不再有卡片色條。建議值（淺）：avoidant `#4B7391`、dependent `#8C5A74`、anxious `#9A7432`、scammer `#4C7F62`、player `#6A5E8C`；深色版各提亮約 25%。人格色不當文字色。
- 按鈕：`.btn.primary` = `--awake` 實心 6px 角；`.btn` 預設 = 透明加 1px `--ink-2` 框；`.btn.danger`（結束並結算）= `--pen` 文字加 `--pen` 框，不填滿。🆘 `.chip.sos` 維持現有位置、尺寸 >= 44px、常駐、無動畫，只換顏色為 `--pen` 框加 `--pen` 字（紅色在這裡是「有人在」，不是警告）。
- 教練：`.coach` 與 `.coach.calm` 結構、內距、邊線寬、字型完全相同，只差底色 token（`--hl` vs `--calm`）。標題「教練備註」；吐槽時多一個「尺度」文字於同一行，不用 emoji 與火焰圖示（現有火焰 SVG 移除，因為只在 roast 出現會成為「有紅旗」的洩漏訊號風險）。
- 安全 modal、求助 modal：沿用現有結構與行為（不可 Esc／遮罩關閉的規則不變）；視覺只換 token，標題色用 `--ink`（不再 `--accent` 粉紅），避免視覺上加戲。
- 同意書：全文保留，勾選框在條款之後；危機條款以 `--hl` 底、`--ink` 字標出，加左側 4px 線，不用紅色（紅色留給批註）。
- 文案（SKILL 的寫作原則）：不用「A · B · C」中點串接，改為「迴避型，宇辰，26 歲」或分兩行；不用「A — B」。按鈕動詞明確：「開始練習」「標紅旗」「看結算」「再玩一次」「換個對象」。不使用連擊、「滿分」、「失敗」、「被騙了」等羞辱或遊戲化計分字眼；結論句用中性事實：「你標出 2 個，共 3 個」。

## 7. 自我檢討：與「任何戀愛遊戲都會做」的預設對照

| 戀愛遊戲預設 | 草案一（我最先想到的） | 檢討後的做法 |
|---|---|---|
| 粉紅漸層、愛心、糖果色 | 先想到「冷色加一點粉當辣度」 | 去掉粉紅。理由：粉色把「被操控」包裝成甜的，與教學目的相反。改為校對三色（青、紅、黃） |
| 大頭像並排當首頁主視覺 | 保留頭像弧但降飽和 | 首頁不放頭像；英雄就是大標。頭像只在選角與聊天用於辨識 |
| 圓潤氣泡加尾巴、我方漸層 | 保留圓氣泡，只換色 | 氣泡 6px、無尾、我方純色。不模仿任何一個通訊軟體的圓潤親密感 |
| 圓角卡片陣列 | 卡片換成直角卡片（這是第 3 種 tell：發絲線加零圓角報紙風） | 不用卡片。清單列加發絲線，圓角只有兩級且有層級邏輯（元件 6px、sheet 頂 16px）。**避開「零圓角報紙風」與「SaaS 圓角卡」兩個極端** |
| 大分數圓環、星級、稱號（火眼金睛） | 草案一保留圓環 | 去掉圓環與稱號感。結算是一句事實加逐句批改，不是成績單 |
| 奶油底加襯線加陶土色（目前 AI 設計最常見） | 一度考慮用米紙感呼應「紙」 | 否決。改冷紙。楷體只放在教練批語，不放標題，避免變成「襯線大標」 |
| 近黑底加霓虹色 | 深色模式想用黑加亮粉 | 深色底改帶藍墨 `#0E151C`，主色是青不是霓虹，紅只用在批註 |
| 每個區塊都有 eyebrow、中點串接 | 草案保留「AI 互動 RPG」膠囊 | 刪除。所有小標籤都要攜帶資訊（難度、階段、已存檔），不然就不要 |
| 入場淡入、hover 抬升 | 保留 persona hover | 刪除。唯一動態是紅筆畫線，且由玩家觸發 |

誠實的殘餘風險：
- 楷體在 Android 多半沒有，會退回黑體，「批語手寫感」在一部分手機上消失。接受這個降級，因為功能與對比不依賴它。
- 「紅筆批註」若實作成太花俏（彈跳、閃爍）會變成裝飾。規範：只有一次 280ms 畫線，沒有別的。
- 青色主色在淺色底上相對冷，需用真機檢查是否過於「醫療」；若是，把 `--awake` 微調偏綠或偏藍即可，不動結構。

## 10. 紅線總對照（方案層級）
- 不用 emoji：全部維持內嵌 SVG；楷體與標籤不依賴符號字元。符合。
- 🆘／需要幫助鈕與首頁危機條常駐、不摺疊、無動畫：只換色，不改 DOM、不加動畫。符合。
- 同意書全文不刪不摺疊、勾選框在條款後：只改外觀。符合。
- 安全 modal 不可 Esc／遮罩關閉：不動 JS。符合。
- 選項樣式一致不依 kind：改為單一列樣式。符合。
- `.coach` 與 `.coach.calm` 結構一致：只差底色。符合。
- 不洩漏紅旗答案：紅筆底線只在玩家標旗後或結算鎖定後出現；教練不新增依紅旗有無而變的視覺。符合。
- 無外部網路資源：系統字型、內嵌 SVG、data URI。符合。
- 尊重 reduced-motion：唯一動態（畫線）在 reduce 下直接呈現終態；全域規則保留。符合。
- 對比 >= 4.5:1：第 8 節實算全數通過；僅「紅字在黃底 4.78」提醒避免。符合，待實作後重驗。
- 不用連擊或羞辱措辭：結論句採中性事實。符合。
- modal／screen 只用 `.hidden`／`.active`：不新增狀態類。符合。

## 11. 未驗證與限制
- 色票對比為 token 配對實算，未量實際渲染（例如 color-mix 的 `--line`、人格降飽和色）。
- 楷體在各平台實際字形與可讀性（尤其 iOS 的 Kaiti TC 小字）未實機看過，需 16px 以上實測。
- 紅筆底線的 SVG data URI 寫法與 `text-decoration: wavy` 在 iOS Safari 的差異未測。
- 結算頁大改（項目 9）可能需要 JS 配合，屬本方案範圍外，需另行排工。
