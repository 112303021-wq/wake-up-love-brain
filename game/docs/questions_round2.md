## 二、新發現（按嚴重度排序）

### Q28【高】刷分仍可行：單字「不要」＋全標 🚩 ＝ 100 分；「對照題」幾乎不存在
**證據**（實測 `s1.py`，5 人格各跑一局，mock，分數依序為 avoidant／dependent／anxious／scammer／player）：

| 策略 | 分數 |
|---|---|
| 每回合自由輸入「不要」＋全標 🚩 | 100／100／96／100／100（火眼金睛） |
| 每回合自由輸入「我拒絕」＋全標 🚩 | 100／100／96／100／100 |
| 每回合選 awake 選項＋全標 🚩 | 98／98／90／98／98 |
| **每回合選 brain 選項（含轉 28 萬）＋全標 🚩** | 45／43／41／45／45 |
| 每回合選 neutral 選項＋全標 🚩 | 51／51／47／51／51 |
| 每回合「嗯」＋全標 🚩 | 51／51／47／51／51 |
| 每回合「不要」，一個都不標 | 55 |
| 每回合選 neutral，一個都不標 | 6 |

**原因**：
1. mock 的 NPC 台詞幾乎全帶紅旗（無紅旗句：avoidant 0／22、dependent 0／24、anxious 2／15、scammer 0／15、player 0／21），所以「全標」的 precision ≈ 100%，誤檢舉扣分（`FALSE_POSITIVE_PENALTY=5`）從未被觸發。
2. `W_DETECT=0.45`，F1 滿分就是 45；加上 `classify_text("不要")` ＝ awake，行為分也滿。
3. 第 1 輪建議的「對照」被實作成**玩家**的 neutral 選項；但誤檢舉測的是 **NPC** 的無紅旗句，兩者不同。neutral 選項不會產生無紅旗的 NPC 句。

**為什麼重要**：現在不需要讀對話就能拿「火眼金睛」。使用者測試與期末成效都會被灌水。

**建議**：(a) mock 與真 LLM 都要在每局安排 ≥ 25–30% 的「正常、無紅旗」NPC 句，並把誤檢舉的懲罰放大（例如 precision 權重、或 F1 乘以 (1−誤檢舉率)）；(b) 自由輸入的 awake 要求有「對象與理由」（至少 ≥ N 字、或與 NPC 前句相關），單字／重複相同句子不計分或遞減；(c) 全標 🚩 設每局上限（例如紅旗總數的 1.5 倍）。
**處理**：後端（計分）、prompt（無紅旗句比例）、研究（效度）。

### Q30【高】語境降級可被利用：把危機包在「遊戲／電影／小說」字眼裡就不終局
**證據**（實測 `safety.assess`）：
- `這個遊戲裡的劇情讓我想自殺` → self_harm / **low** / fiction
- `我想自殺，像電影那樣` → low / fiction
- `小說裡的主角想死，我也是` → low / fiction（`_SELF_AFTER` 只在第三人稱分支才生效，fiction 分支先 return）
- `演戲演到我想死` → low / fiction
- `你走了，活不下去` → low / third_person（`你` 被列入 `_THIRD_MARKERS`，句中沒有「我」）
- 規則在 `engine/safety.py` `_context`：只要全句出現 `_FICTION` 詞且沒有 `_REAL` 詞（現實、真的、認真…）就整句降級。

**為什麼重要**：「這個遊戲讓我想自殺」正是最需要被接住的情況（遊戲內容觸發真實痛苦），反而被當成劇情。意圖明確的第一人稱（`我想自殺`）在同句有「像電影那樣」時也被降級。

**建議**：fiction 降級只適用於「主詞明確是別人／角色」；只要出現第一人稱主詞＋危機動詞，就維持 high（`遊戲`、`電影` 不得抵銷）；`你` 不應列入第三人稱標記；low 的提醒要附 1925，且 UI 提供「我是在說我自己」一鍵升級。
**處理**：後端、研究。

### Q31【高】模型拒答或跳戲＝整局永久結束，且對無危機玩家顯示 3 條熱線
**證據**（實測 `v2.py`）：LLM 回 `{"reply":"","red_flags":[],"break_character":true}`（`ClaudeLLM` 遇 `stop_reason=="refusal"` 就是這個輸出）：首回合就 `ended=True`、`safety.category="model"`、`resources` 有 3 筆、`can_resume=False`；`message` 只有「我們先暫停一下遊戲。（這不是遊戲裡的角色在說話…）」。模型自己寫的 `reply`（`model_text`）前端從不顯示（`showSafety` 只讀 `sf.message`）。

**為什麼重要**：愛情詐騙情境本身很容易觸發安全分類器拒答。一次拒答就讓玩家失去整局（只能 reset），還被塞三條危機熱線，像是被判定有危機。這會污染使用者測試資料（誤把技術問題當成安全事件），也可能讓真正有狀況的人覺得熱線訊息是罐頭。

**建議**：區分「refusal（技術）」與「模型判斷玩家有危機」。refusal → 重試／用 fallback 台詞／換模型，不終局、不顯示熱線；模型判斷危機 → 顯示 `model_text`，並與規則式一致地處理；`model` 類別允許 resume 或至少保留進度。
**處理**：後端、prompt。

### Q32【高】自由輸入的順從／轉帳判定漏洞：真正轉錢卻 neutral、金額 0
**證據**（實測 `scoring.classify_text` / `money_in_text`）：

| 輸入 | kind | 金額 |
|---|---|---|
| 我轉你五萬，不要客氣 | neutral | 50000 抽到但 `kind≠brain` 不計入（`game.py:_send_locked` 只在 `kind=="brain"` 才呼叫 `money_in_text`） |
| 我不要你難過，我轉你五萬 | neutral | 同上 |
| 不要懷疑我，我轉給你了 | neutral | 同上 |
| 我拒絕不了你，我轉 | neutral | 同上 |
| 我會把存款全部給你／我把錢都給你／我會幫你付／我去ATM領錢給你 | neutral | 0 |
| 已匯款／我先轉帳過去 | neutral | 5000（預設值，未計入因為 neutral） |
| 我不會不轉（雙重否定＝會轉） | awake | 0 |
| 我借你一百萬／我匯給你兩百萬元 | brain | 1000000／2000000 |

**為什麼重要**：判定規則是「同句有任何拒絕詞（不要、拒絕）就與強順從互相抵銷成 neutral」。人在情緒下常說「我不要你難過，我轉」；這是教學上最該被抓的一刻，卻沒有教練插話、沒有金額、被騙指數不增。反向：同一套規則讓「不要」單字拿滿分（Q28）。

**建議**：金額抽取與 kind 分開（有轉帳意圖就記金額，不論是否同時有拒絕詞）；加入「全部給你／領錢／ATM／代墊」等詞；雙重否定；自由輸入的最終判定交給 LLM 評審（附理由），regex 只當 fallback；建立 ≥ 100 句標註集量準確率。
**處理**：後端、prompt（評審）、研究（標註）。

### Q33【中】safety 誤終局：否定句、拒絕句、玩笑與年齡數字
**證據**（實測）：
- 否定句被終局（high）：`我沒有想死`、`我不是想自殺`（`_N` 否定守衛只看前 1 字，`沒有`、`不是` 無效；`自殺` 本身無守衛）。
- 玩家正在拒絕卻被當真：`傳裸照給我？你瘋了嗎`、`你叫我傳裸照，我拒絕` → real_scam / high（`裸照` 單詞即觸發）。
- 誇飾：`考試考爛想死`、`這工作要我命，想死`、`我去死好了哈哈`、`想消失在人群裡，不想社交` → 終局（`_HYPERBOLE` 只認 `累到` 這類固定前綴）。
- **迴歸**：`我5歲就會彈琴了` → minor（新規則 `(\d|…|[一二三四五六七八九])歲` 把 1–9 歲都算）。
- 每次終局都需要 reset 才能重玩（self_harm／real_scam 不可 resume）。

**為什麼重要**：誤終局的成本是玩家被中斷、被當作危機；玩家學會不誠實。與 Q29 的漏判是同一組規則的兩側。

**建議**：否定與拒絕要在 `裸照／自殺／想死` 前 6 字內判斷；`裸照` 只在「要我傳／拍／給」的語境觸發；低信心一律降為 low＋可一鍵升級（見 Q30）；minor 的年齡必須 ≥ 10 或配合「我」＋年齡語境。
**處理**：後端。

### Q34【中】pause／ai_identity 規則會打斷玩家的「清醒行為」
**證據**（實測 `safety.assess`）：
- `你別玩了，我知道你在騙我`、`你不要玩了，我不會匯款` → **pause**（medium，終局）。這是玩家最理想的回應，卻被當成「我要退出遊戲」，該回合不計分、不推進劇情。
- `結束遊戲般的曖昧`、`我想退出這個話題`、`我先停一下，去洗澡` → pause。
- `你是真人你就視訊`、`你是bot嗎，講話好制式` → ai_identity，系統回覆「我是 AI 驅動的模擬角色…」，**NPC 不回話、不計分**。「要求視訊」是詐騙防範的核心行為，卻被攔截。
- `你是程式設計師嗎`、`你是電腦系的嗎`、`你是人工智慧工程師嗎` → ai_identity（正規式 `你是(…程式|電腦|人工智慧…)` 沒有收尾界線）。

**為什麼重要**：教學上要鼓勵的「質疑、要求視訊、叫對方別玩了」反而最容易被規則誤判。

**建議**：pause 必須以第一人稱（我）為主詞，「你別玩了」不算；ai_identity 要求句尾疑問（嗎／是不是）且排除條件句（你是…就…）與職業詞；把「要求視訊」「叫對方停止」記為 awake 行為並推進劇情。
**處理**：後端。

### Q35【中】resume 沒有把關，且可無限循環
**證據**（實測）：`真的撐不下去了` → too_painful、`can_resume=True`；`POST /api/resume` 立即成功。`我不玩了` → resume 循環 30 次，messages 累加到 61，無次數／冷卻限制。`self_harm` 終局後雖不可 resume，但玩家可直接切另一個人格或 `reset` 後立即繼續玩（safety 狀態是 per-session，第 1 輪 Q15 同一問題）。

**為什麼重要**：too_painful 是「這些對話勾起真實痛苦」。一鍵回到遊戲、沒有確認「你現在還好嗎」，與設計初衷相反。

**建議**：too_painful 的 resume 需先有一個確認步驟（顯示資源＋「我想休息／我想繼續」），並記錄次數；同一玩家在 N 分鐘內第二次 too_painful 禁止立刻 resume；safety 狀態上提到 profile 層級（跨人格）。
**處理**：後端、前端、研究（處置流程）。

### Q36【中】無認證的資料刪除與玩家 ID 品質
**證據**（實測 `v2.py`）：
- `GET /api/profile?player=victim001`（無任何憑證）可讀；`DELETE /api/profile?player=victim001` → `{"ok":true,"deleted":true}`；再讀為空。任何知道 ID 的人都能刪別人的存檔、成績、同意紀錄。
- 1 字元 ID `a` 可建檔；匿名依序建立 `spam0…spam299` → 300 個 JSON 檔，無配額、無速率限制。
- 前端 ID 為 `"p" + Math.random().toString(36)`（非密碼學隨機，V8 的 xorshift 在觀察多個輸出後可預測）。
- 風險緩解：POST／DELETE 需 `application/json` 或非簡單方法，跨站請求會被瀏覽器預檢擋下（實測 `OPTIONS` 回 501，且無 CORS 標頭），所以不是遠端網頁攻擊，而是「ID 外洩」或「同網段猜測短 ID」。

**建議**：由後端簽發 128 bit 隨機 ID，並以 HttpOnly cookie 或簽名 token 作為憑證（ID 本身不當憑證）；刪除需 token；建檔速率限制＋總量上限；拒絕長度 < 16 的 ID。
**處理**：後端、前端。

### Q37【中】前端與 api_contract 的不一致

**建議**：前端補呼叫 `/api/consent`（附版本與 ts）與 `/api/prefs`；`detectDev` 改讀 `/api/resources.dev`；刪除說明改成實際行為；等級單一來源（後端回傳 `grade`，前端只顯示）。
**處理**：前端（主）、後端（文件）。

### Q38【中】教育設計：選項洩題只修一半；neutral「對照題」不足以量測誤判
**證據**（`data/personas.json` 實測）：
- **位置洩題已修**：每局每階段順序依 seed 打散（`choices(stage, seed)`）。
- **詞彙洩題仍在**：愛情騙子 5 個 awake 選項**全部**含「不／沒」（`薪水不聊`、`沒有穩賺不賠`、`我不轉帳也不投資`、`這我不接受`、`我不會再匯款了`），brain 選項 0／5 含；依賴型 awake 僅 1／5 含、brain 4／5 含（反過來）。結果「選有否定詞的」在愛情騙子上就是 100% 解法，且 `lexical` 策略在愛情騙子拿 55，其他人格 0–17（說明各人格洩題方向不一致）。
- **語意漫畫化**：brain 選項多半是「好，我先轉一萬試試看」「我再去湊五萬當保證金」這種一眼就知道錯的句子；awake 選項都是明確拒絕。沒有「溫和但清醒」「看起來清醒其實是順從」「禮貌拒絕卻留後門」等中間型，無法區分理解與關鍵字比對。
- **neutral 選項是離題對照**：例如愛情騙子第 4 階 NPC 在催保證金，neutral 選項是「我今天要加班，晚點再跟你說話好嗎？」，與 NPC 前句無關。它能被「與上一句不相干」辨識，也不產生 NPC 無紅旗句（Q28），所以不能測「過度警覺」。
- **neutral 的出口**：`neutral` 選項不被教練評論、被騙指數只算半個順從；全選 neutral＋全標 🚩 ＝ 51（高於全選 brain 的 45，差 6 分，見 Q39）。

**為什麼重要**：這是第 1 輪 Q9 的核心。只調順序與字數不足以讓選擇題量到「辨識」；對照題設計沒有對應到想量的構念（過度警覺／誤判）。

**建議**：每階段至少 1 個 NPC 無紅旗句＋對應的「正常回應」與「過度防衛」選項，作為真正的對照題；awake／brain 選項互相交換否定詞比例（brain 也有「不好意思，我不想讓你失望」）；加入中間難度選項；上線前用 ≥ 10 位受測者做項目分析（鑑別度、與關鍵字的相關）。
**處理**：研究（主）、prompt（選項改寫）。

### Q39【中】分數對被騙金額幾乎不敏感
**證據**（實測 `s1.py`）：愛情騙子每回合選 brain（累計匯出 1+5+20 萬遊戲幣等）＋全標 🚩 ＝ 45；選 neutral＋全標 ＝ 51。`MONEY_PENALTY_BEHAVIOR=15`、`MONEY_PENALTY_PER_EVENT=10` 只在事件數上累加，不看金額；`fooled` 上限 100。
**為什麼重要**：「把 28 萬匯給騙子」與「單純敷衍」只差 6 分，結算頁以「觀察中」帶過；與詐騙案實際損失（金額）脫節。
**建議**：被騙指數以金額（相對玩家設定的財力或對數尺度）計；有任何匯款事件的局，等級上限封頂（例如不得高於「警覺升級」）。
**處理**：後端、研究。

### Q40【中】教練稱讚「拒絕正常訊息」，與過度警覺的教學目標衝突
**證據**：`engine/coach.py` `interject`：`kind=="awake"` 一律回 praise，不看 `last_npc` 有沒有紅旗；`scoring` 的行為分 `(awake−brain)/n_turns` 同樣不看對方那句是否正常。
**為什麼重要**：玩家對無紅旗的正常句也拒絕，仍被稱讚＋加分。與前端「這句其實還好，別草木皆兵」的訊息、與誤檢舉扣分互相矛盾。
**建議**：awake 只在對方有紅旗時加分／稱讚；對方正常時拒絕 → 教練溫和提示「這句其實可以正常回」，行為分不加。
**處理**：後端。

### Q41【中】愛情騙子 prompt 殘留的有害指示
**證據**（`personas/npc_愛情騙子_prompt_final.md`）：第 58 行「玩家向你求助或表達沒錢：引導去信貸、找朋友借、用信用卡刷卡預支」；第 59 行「玩家表現出強烈情緒（哭、崩潰）：…的口吻繼續施壓；但若是在談現實中的痛苦，改走安全規則」；第 86 行台詞「你身上真的沒錢了嗎？去跟銀行辦信貸很快的」。
**為什麼重要**：「是不是現實痛苦」要模型自己判斷，而規則式 safety 對很多說法漏判（Q29）。模型一旦判錯，就會對真實崩潰的玩家「繼續施壓」。
**建議**：把「哭／崩潰」情境改成一律降壓並詢問玩家是否要暫停；貸款指引只能在明確標示為 NPC 台詞的位置，不得出現在行為規則（容易被誤用為建議）。
**處理**：prompt、研究。
