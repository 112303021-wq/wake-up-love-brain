# 教育成效衡量設計（第 2 輪）

版本：2026-11-08　撰寫：使用者研究員　對應：Q9（成效無量測、選項洩題）、research_plan.md RQ2 / RQ7

## 0. 先講清楚：我們不宣稱什麼

- 本研究是**探索性、小樣本、單組前後比較**，沒有對照組時只能說「玩家在遊戲後的辨識表現有／沒有變化」，**不能說「遊戲有效」，更不能說「大幅有效」或「能防詐」**。
- 即使有變化，也可能來自：測驗熟悉、受測者猜到研究目的（需求特徵）、玩家在實驗室裡本來就更警覺、題目難度不均。
- 實驗室判斷題不等於真實情境下的行為；我們量的是「辨識訊息中的紅旗」，不是「真的不被騙」。
- 對照文獻：最接近的愛情詐騙遊戲隨機對照試驗（英國 4,201 人，預印本，尚未同儕審查）4 週後遊戲組 75%、文字組 71%、對照組 70%，差距很小（細節見 concept_definition.md 第 2 輪查證）。我們的原型更小、更簡單，**預期效果不會比它大**。報告時請用「初步」「探索」「需更大樣本」等字。

建議簡報／報告的標準用語：
> 「在 N 位受測者的小規模前後比較中，紅旗辨識的 d' 由 X 變為 Y（95% 信賴區間 …）。樣本小、無對照組，結果僅供探索，不能推論為防詐成效。」

## 1. 研究設計

| 階段 | 時間 | 內容 | 時間成本 |
|---|---|---|---|
| 前測 T0 | 玩遊戲前 | 12 題辨識測驗（表 A 組）＋基本資料＋信心 | 5 分鐘 |
| 介入 | T0 後立刻 | 玩 1–2 局（建議固定：愛情騙子 1 局＋任一人格 1 局），尺度以預設（溫柔）為主，其餘依 usability 流程輪流 | 15–20 分鐘 |
| 後測 T1 | 玩完立刻 | 12 題（表 B 組）＋事後問卷（羞恥感、教練語氣接受度，第 5 節）| 6 分鐘 |
| 延遲測 T2 | 7 天後（容許 6–9 天），以 LINE／Email 發連結 | 12 題（表 C 組）＋1 題「這週有沒有遇到可疑訊息？」| 5 分鐘 |

- **A／B／C 三組題等值輪替**：受測者隨機分到 A→B→C、B→C→A、C→A→B 三種順序（反制衡），避免「某組題本來比較簡單」被誤當成進步。每組題的紅旗種類與難度配對（見第 3 節）。
- 若人力有限，至少做 T0＋T1，T2 作為加分項。T2 流失率預期 30–50%，請在招募時就取得同意與提醒方式。
- 可選的對照（若組員有餘力，**非必須**）：另找 15–20 人只讀「紅旗懶人包」（約 500 字，不是遊戲）後做 T1 題目。這樣才能談「遊戲 vs 閱讀」。沒有這組，就只能寫「前後變化」。

## 2. 量尺與計分

每題流程：看一則訊息（或兩三句對話）→ 判斷「有紅旗／沒紅旗」→ 若選有紅旗，再從 8 個**白話類別**選一個（不用內部英文代碼）→ 信心 1–5。

### 2.1 主要指標：d'（敏感度）

- 以「有紅旗」為訊號。命中 H = 紅旗題判有紅旗的題數；誤報 FA = 正常題判有紅旗的題數。
- 一組題 9 題紅旗＋3 題正常，所以極端值很常見（0%、100%）。用 **log-linear 校正**：
  - 命中率 = (H + 0.5) / (9 + 1)；誤報率 = (FA + 0.5) / (3 + 1)
  - d' = z(命中率) − z(誤報率)；偏誤 c = −[z(命中率) + z(誤報率)] / 2
- 次要指標（比 d' 容易向組員解釋）：
  - **Recall（命中率）** = 紅旗題中判對「有紅旗」的比例
  - **Precision（精準度）** = 判「有紅旗」的題目中，真的有紅旗的比例（受正常題影響，這是 Q9 要求的對照）
  - **類別正確率**：判有紅旗且類別也選對的比例
  - **過度多疑指標**：正常題誤報率（若玩完後誤報大增，代表變成「什麼都懷疑」，是負面結果，要如實報）
- 每人的 d'、Recall、Precision 都算 T0、T1、T2；報告個別變化的分布，不只報平均。

### 2.2 為何只有 3 題正常題不夠理想

誤報率只有 0、1/3、2/3、1 四種值，很粗。**建議**：T0／T1／T2 各加到 16 題（10 紅旗＋6 正常，約 6 分鐘）；若題數受限，維持 12 題，但在報告中承認 d' 的不穩定。以下題庫先給 12 題（9＋3）一組，並附 3 題備用正常題（每組 +1），請組員決定要採 12 或 16 題。

## 3. 題庫（A、B、C 三組，各 12 題）

### 3.1 與 personas.json 紅旗代碼的對應

`personas.json` 內五個人格共 11 至 12 個紅旗代碼。本測驗涵蓋其中的**核心 8 類**（白話類別名 → 代碼）：

| 測驗類別（受測者看到的名稱） | 對應代碼 |
|---|---|
| 1. 太快太親密／急著定關係 | `fast_intimacy`, `no_label`（反向：不定義關係）|
| 2. 畫未來的大餅 | `future_faking`, `say_do_gap` |
| 3. 打聽你的財務 | `probe_finance` |
| 4. 炫耀獲利／內線機會 | `show_wealth`, `insider_tip`, `small_invest` |
| 5. 要錢或要你借貸 | `urgent_money`, `pressure_loan`, `withdraw_fee` |
| 6. 情緒勒索／把問題推給你 | `guilt_trip`, `breakup_threat`, `blame_shift`, `deny_said`, `loyalty_test`, `attention_comparison` |
| 7. 忽冷忽熱／消失 | `push_pull`, `ghosting`, `need_space`, `stonewalling`, `breadcrumb`, `mixed_signal`, `late_night_only` |
| 8. 控制行蹤／過度查勤／切斷你的生活 | `excessive_checking`, `reply_pressure`, `secrecy`, `boundary_blur`, `probing_private`, `self_sacrifice` |

未納入測驗的代碼（`over_apology`、`low_self_worth`、`defer_decisions` 等玩家端或依賴型內在狀態，不易靠單句訊息判斷）：在第 6 節限制註明。

注意：依賴型、焦慮型、迴避型的代碼是**互動模式**，不是詐騙，題目措辭要保持「關係風險」而非「詐騙」。

### 3.2 防洩題規則（硬性）

1. **不得與遊戲內任何文字重複**：不用 `personas.json` 的 `choices` 選項原文，不用 NPC mock 台詞原文，不用 `quiz_and_retention.md` 第 1–12 題原文。測驗句子一律另寫（釋義、換場景、換身分）。
2. 避開遊戲內明顯的提示詞：「詐騙」「165」「封鎖」「檢舉」「穩賺不賠」「保證金」「寶貝」「老公」「戀愛腦」。題目與選項都不出現這些詞。
3. 題目不出現紅旗代碼；類別選項順序**每題隨機**。
4. 紅旗題的線索要靠語意，不靠關鍵字；正常題刻意包含「談錢」「撒嬌」「想見面」「說忙」等表面像紅旗的內容，才測得到精準度。
5. 測驗放在遊戲網站之外（Google 表單／Qualtrics 類），**遊戲的 reveal 與覆盤 API 在測試期關閉**（GAME_DEV 不開），受測者玩完遊戲前不可見答案。
6. T0 與 T1 之間受測者不會收到答案；全部測完（含 T2）才揭曉正解。避免回饋汙染下一次測量。
7. 提供作答資料前先 pilot 2 人，檢查語句是否太像某條遊戲台詞。

### 3.4 B、C 組編寫要點（給組員實際寫題）

- 每組同樣 9 紅旗（8 類各 1，外加類別 6 或 7 再 1）＋3 正常（正常題各涵蓋：談錢無索取、因忙而延遲回覆、表達喜歡不施壓）。
- 場景換：交友軟體／IG 限動／同學社團／遊戲公會／讀書會，避免都是 LINE 單聊。
- 難度配對：每個類別在三組各有「明顯版」與「隱晦版」，各組比例相同（A、B、C 的明顯：隱晦 = 5：4）。pilot 時用 2 位非受測者估各題通過率，配對偏離過大的題目替換。
- 正常題要像紅旗（見規則 4），以免精準度測不出差異。
- 另設 3 題「備用正常題」／組，在採 16 題版時使用。

## 4. 樣本量粗估（誠實版）

假設：雙尾 alpha = 0.05、power = 0.80、單組前後配對 t 檢定（粗略用 n ≈ 7.84 / d² ＋少量修正）。

| 想偵測的效果量（Cohen's dz） | 需要完整配對樣本 | 備註 |
|---|---|---|
| 0.5（中等）| 約 34 | 對 d' 前後變化而言，已算樂觀 |
| 0.3（小到中）| 約 90 | 超出本專題能力 |
| 0.2（小）| 約 200 | 同上 |

- 研究計畫目標是 30–50 份問卷。**實際上只有在效果量約 0.5 以上時，才有合理機會偵測到**。若真實效果較小（文獻顯示可能如此），我們多半會得到「看不出顯著差異」，**這不代表遊戲無效，只是樣本不足，**同時也不代表有效。
- T2 流失 30–50%：要在 T2 得到 30 人，需招募約 50–60 人進 T0。若做不到，T2 只做描述。
- 兩組比較（遊戲 vs 懶人包）偵測 d = 0.5 每組約 64 人，**目前不可行**，除非另有資源。因此若做對照組，也只當探索。
- 統計報告方式：以效果量與 95% 信賴區間為主（含 bootstrapping），不以 p 值作結論；不做事後多重檢定挖掘。**預先登記**：主要指標為 T0→T1 的 d' 變化；次要指標為 Recall、Precision、誤報率、T0→T2 的 d'。
- 缺漏資料處理：T2 缺漏者不補值；報告流失人數與是否與 T1 表現相關。
- 提醒：統計背景組員可用 R（`psycho`、`pwr` 套件）自行驗算；上列數字為粗估，需由統計組員核對。

## 5. 事後問卷（搭配 T1，與倫理對應）

均為 1–5 同意度，單題即可（避免問卷過長）：

1. 教練的話我聽得進去。（RQ3）
2. 教練的話讓我覺得被批評或丟臉。（羞恥感，若平均 ≥ 3 或有人 ≥ 4，需檢討語氣，詳見 coach_tone_guidelines.md）
3. 我覺得自己比較知道要注意哪些警訊。（自我效能；**注意：自評不等於能力**）
4. 玩的過程中有不舒服到想停下來。（0 次／1 次／多次）
5. 我會推薦朋友玩。（RQ5）
6. 開放題：最讓你不舒服或想修改的一句話是什麼？

## 6. 已知限制（必須寫進報告）

1. 小樣本、方便樣本（政大學生為主）、自願參與，結果不能推到一般大學生或長者。
2. 單組前後測無法排除：測驗效應、成熟、霍桑效應、需求特徵。
3. 實驗室情境下受測者知道主題，會比真實更警覺；題目是文字訊息，缺少真實詐騙的壓力、時間與情感投入。
4. 題庫自編，未經信度與效度檢驗；A／B／C 組難度只能靠 pilot 粗略配平，仍可能不等。
5. 部分互動模式型代碼（依賴型、焦慮型）不易用單句判斷，測驗對它們的涵蓋較弱。
6. 目前遊戲 AI 為 mock 模式，若接上 LLM，體驗不同，需要重新評估。
7. 3 題正常題導致精準度與誤報率估計不穩（見 2.2）。
8. 這是教育與娛樂用途，不是心理診斷，也不保證防詐。

## 7. 資料紀錄欄位（給後端／前端）

每位受測者一列（匿名 ID P01…，不放暱稱、LINE ID）：`pid, order(ABC/BCA/CAB), form, item_id, shown_order, judged_flag(0/1), category_chosen, confidence, response_ms, timestamp`；另存遊戲版本、尺度、局數。對照代碼的答案檔與受測版分開存放。

## 8. 需要真人決定

- 採 12 或 16 題／組；要不要做懶人包對照組。
- 組員／老師是否接受「不宣稱有效，只做探索」的框架（建議接受）。
- A、B、C 組題目由誰寫（建議兩位組員各寫，對方審查是否像遊戲內台詞）。
- 酬謝與 T2 提醒方式（LINE／Email）。
