# 第 3 次會議紀錄（2026-11-08）

輸入：questions_round3.md（Q28–Q45 驗證：已解 9、部分 7、未解 2、迴歸 0；新增 Q46–Q59 共 14 題）。測試 630 項全過。

## 最重要的結論：safety 詞庫無法靠繼續加詞解決

- 第 2 輪的 201 句：0 不符。這是「針對測試集修」的結果。
- 質疑者全新寫的 218 句：該終局的 92 句漏 74 句（80%）。第一人稱自傷召回 1/46（2%）。連「我欲去死」「i wish i was dead」都漏。
- 誤終局 6/90，包括遊戲內對 NPC 說「我剛剛匯了五萬到你的帳戶」（入戲轉帳被當現實詐騙）。

結論：
1. 關鍵字／規則式 safety 本質上泛化差，繼續堆詞庫只會再次過擬合。不得再用「0 不符」宣稱 safety 已解。
2. 本專案不是危機介入工具。對外必須明確寫「本遊戲不能偵測所有危機情況」，並讓 🆘 求助入口在所有畫面永遠可見（已做）。
3. 若要實質改善，需要 LLM 第二道分類器（或 embedding 分類），這牽涉「是否使用外部 LLM」的待決事項。本輪先做可插拔介面、預設關閉，並修已知的誤終局與結構性規則。
4. 驗收方式改為：保留一份「盲測集」不放進 repo 的測試，由質疑者每輪重寫，不再讓開發者看到。
